# Quantization-Aware Training of AutoML-Optimized NIDS Models

Code and firmware accompanying the paper *Quantization-Aware Training of AutoML-Optimized Deep
Learning Models for Edge Network Intrusion Detection* (anonymized for review).

The pipeline takes the neural network that AutoGluon selects for binary intrusion detection, rebuilds its topology in
PyTorch, trains it there with Quantization-Aware Training (QAT) after a preprocessing step aimed at the near-zero feature
values that collapse under INT8 quantization, and exports the result as an int8 model (integer matrix products with int32
accumulation and one float32 requantization multiplier per layer) that runs on an M5Stack Basic (ESP32). It is run on four datasets with the same procedure: the corrected release of
[CICIDS2017](https://www.unb.ca/cic/datasets/ids-2017.html) (`CICIDS2017_improved`),
[UNSW-NB15](https://research.unsw.edu.au/projects/unsw-nb15-dataset), TON_IoT (network data) and
[CICIoT2023](https://www.unb.ca/cic/datasets/iotdataset-2023.html).

## Pipeline

1. **AutoML baseline**: AutoGluon searches architecture and hyperparameters (`automl_model_search.py`).
2. **Cross-framework translation**: the topology selected by AutoGluon (layer sizes, activations, dropout; BatchNorm
   replaced by Identity unless `--keep_batchnorm`) is rebuilt in PyTorch and trained there, the weights of the AutoGluon
   network are not transferred, so that PyTorch's QAT tooling can be used (`autogluon_to_pytorch_qat.py`;
   `verify_functional_equivalence.py` compares the predictions of the two models on the test set).
3. **QAT** with `QuantStub`/`DeQuantStub` and the qnnpack configuration.
4. **Near-zero feature rescaling** (`--scale_close_to_zero`, factor set by `--scale_factor`).
5. **Feature selection** by sequential backward elimination (`feature_ranking.py`, `--prune_features`).
6. **INT8 export and on-device evaluation** on the M5Stack (`examples/IoT_test/m5stack_ids_eval/`).

## Repository layout

```
requirements.txt                          software stack of the paper (Python 3.11, AutoGluon 1.6.2, PyTorch 2.4.1)
cluster/                                  SLURM job scripts
examples/CICIDS2017/scripts/              all pipeline and analysis scripts (see examples/CICIDS2017/README.md)
examples/CICIDS2017/docs/EXPERIMENTS_LOG.md   commands of the experiments of the paper
examples/CICIoT2023/                      how the second dataset is built (reuses the CICIDS2017 scripts)
examples/IoT_test/m5stack_ids_eval/       M5Stack deployment: INT8 export, firmware, device benchmark
```

Only code, documentation and firmware sources are included. Datasets, AutoGluon predictors, trained checkpoints,
training logs and result tables are generated by the pipeline (see the dataset steps in
[`examples/CICIDS2017/README.md`](examples/CICIDS2017/README.md)); the analysis scripts write their tables and figures
to `paper_results/`, which is not versioned.

## Setup

The pinned software stack is that of the paper (Python 3.11).

```bash
python -m venv .venv
source .venv/bin/activate        # .venv\Scripts\activate on Windows
pip install -r requirements.txt
```

AutoGluon needs a small patch to run the hyperparameter search, see
[`examples/CICIDS2017/scripts/patches/README.md`](examples/CICIDS2017/scripts/patches/README.md). To run on a SLURM GPU
cluster, see [`cluster/README.md`](cluster/README.md).

## Experiments of the paper

Every dataset is run with the same experiments, numbered as in the paper (`run_multiseed.py --experiment N`; the
definitions are in `examples/CICIDS2017/scripts/utils/experiments.py`):

| Exp. | Description |
|---|---|
| 1 | baseline, no early stopping, no LR scheduling |
| 2 | early stopping enabled |
| 3 | LR scheduling enabled |
| 4 | near-zero feature scaling (x1e6) |
| 5 | Exp. 4 + feature selection (run for reproducibility; not reported in the paper) |
| 6, 7, 8 | Exp. 3 with standardization, logarithmic Min-Max or a quantile transform of the input instead of the near-zero rescaling (input-representation comparison) |

Each experiment is repeated over 5 seeds, seed *i* on its own data split `split_<i>`. A run of experiment *N* with
seed *S* is stored as `*_exp<100000 + N*100 + S>.pth` / `execution_log_exp<...>.txt` next to the checkpoints.
`examples/CICIDS2017/docs/EXPERIMENTS_LOG.md` lists the commands, and `cluster/submit_experiments.sh` submits the whole
sequence for one dataset on a SLURM cluster.

## On-device evaluation

`examples/IoT_test/m5stack_ids_eval/INT8_DEPLOYMENT.md` describes how a QAT checkpoint is exported to int8 weights
and requantization multipliers, checked bit by bit against an integer emulation, and flashed.
`examples/IoT_test/m5stack_ids_eval/device_bench/README.md` describes the benchmark that runs the full test set on
the board (accuracy, latency distribution, memory, throughput).

The host-side scripts read the Experiment 4 checkpoints under the names `normal_pytorch_model_exp6.pth` and
`qat_pytorch_model_exp6.pth` (historical names: copy the seed-0 pair, `*_exp100400.pth`, to
`examples/IoT_test/m5stack_ids_eval/` with those names). The exported firmware headers (`exp6_qat_int8_model.h`,
`exp6_normal_model.h`) are included, so the validated sketches compile without retraining;
`device_bench/make_bench_samples.py` generates `bench_samples.h` for the benchmark sketches.
